# A01 · Personal Project History

**Level:** Beginner · **Estimated time:** 2 hours · **Related:** [Module 03](../modules/README.md)

## Objective

Build a small project (any language, or a docs site) from scratch with a clean, meaningful Git history.

## Requirements

1. At least 12 commits, each one logical change.
2. Every message follows Conventional Commits, with an explanation in the body for at least 4 of them.
3. Use `git add -p` at least twice to split unrelated edits into separate commits (mention which commits in your README).
4. A proper `.gitignore` and `.gitattributes`.
5. Push to your own GitHub or GitLab account.

## Deliverables

- Repository link
- README.md with a 'History notes' section explaining 3 commits you split with `add -p`

## Grading rubric

| Criterion | Points |
|---|---|
| Commit granularity | 30 |
| Message quality | 30 |
| Ignore/attributes setup | 20 |
| README explanation | 20 |
| **Total** | **100** |

## Stretch goal

Add a `git log` alias that prints your history in one line per commit, and show its output in the README.

## Submission tip

Put everything in a public repository named `git-mastery-a01-personal-project-history` and share it on LinkedIn with **#DevOpsShack** and **#GitMastery**. A recruiter-visible Git portfolio is worth more than a certificate line on its own.
