# Git Interview Questions · 1,000 Questions with Answers

Three banks, built for how Git is actually tested in DevOps, SRE, platform and software engineering interviews.

| Bank | Questions | What it tests |
|---|---|---|
| [Concept-Based Questions](01-concept-based/README.md) | 300 | Definitions, internals and the reasoning behind Git's design. These test whether you truly understand how Git works. |
| [Scenario-Based Questions](02-scenario-based/README.md) | 350 | "You did X, now Y happened. What do you do?" Practical situations every engineer meets, with the exact commands to get out of them. |
| [Production-Based Questions](03-production-based/README.md) | 350 | Real company situations: incidents, CI/CD, GitOps, security, compliance, scale, migrations and release engineering. This is where senior DevOps interviews are won. |

## How to use these banks

**Answer out loud first.** Read the question, say your answer as you would in an interview, then open the answer. Interviewers care about how you reason, not only about the final command.

**Explain the why.** For every command, be ready to say what it does to the working tree, the index and the commit graph. That's what separates a memorized answer from understanding.

**Practise the scenarios for real.** Most scenario and production questions map directly to a [hands-on lab](../labs/README.md). Reproduce the situation, break it, then fix it.

**Suggested order**

1. Concept-based, questions 1–150 (fundamentals, internals, history)
2. Scenario-based, all 350
3. Concept-based, questions 151–300
4. Production-based, all 350

If you're short on time before an interview, do the production bank's incident, CI/CD and GitOps sections. They come up most in DevOps rounds.
